# VPN 分流管理器

一個 Windows Rust GUI，用來把指定的 IPv4 目的網段或網域綁定到 FortiClient、F5 或 Ivanti 的 VPN 虛擬網路介面。

## 設計行為

- 三個 VPN 各有獨立開關、介面選擇，以及可混合填寫 IPv4 CIDR、IPv4、網域與完整網址的輸入區；內容超過四列時會在輸入區內顯示垂直捲軸，不會把卡片撐出畫面。
- 視窗預設以 `1280 × 720` 啟動，可拖曳邊界自由調整大小；三個 VPN 會依可用寬度自動切換為三欄、兩欄或單欄，卡片與輸入區會延伸使用剩餘視窗高度，高度不足時則可垂直捲動。卡片的欄距、列距、視窗左右留白，以及最後一列到下方狀態列的留白皆維持一致，且不讀取舊版曾保存的視窗大小。
- 程式會自動選擇唯一正在連線的 VPN 虛擬網卡；只有同時出現多張候選網卡時才需要手動選擇。
- 瀏覽器啟動的 F5 Network Access 會另外建立動態 RAS/PPP 介面；程式會偵測真正承載 VPN IP 與路由的介面，而不是誤用固定安裝但顯示中斷的 F5 驅動網卡。
- 開啟開關時會立即在背景驗證並建立路由，不需要另外按套用；只有使用者主動要求的偵測或路由變更會顯示進度並暫時鎖住衝突控制項。週期健康檢查與 DNS 更新不會讓整個畫面變灰或顯示轉圈；若剛好在背景檢查時操作，要求會安全排隊並於檢查完成後執行。
- 分流關閉時按鈕顯示「啟用分流」，成功開啟後改為「停用分流」。
- 啟用期間若驗證、介面偵測、路由套用或背景工作發生任何錯誤，會以彈跳視窗顯示實際原因，並把開關恢復原狀。
- 不同已開啟區域只要有網段重疊，就會阻擋開啟、在彈跳視窗顯示原因並把開關恢復原狀。
- 關閉開關時會立即移除本程式先前替該 VPN 建立的路由。
- 同一個 Windows 使用者工作階段只允許一個程式實例，避免兩個視窗同時改寫同一套路由清單。
- 啟用期間會鎖定介面及網段欄位；先關閉並成功移除路由後即可修改。
- 所有路由只寫入 Windows `ActiveStore`；正常關閉程式時會逐條盡力移除、遇到路由表競態會重試，並把開關保存為停用。若程式異常終止，殘留路由會在下次啟動先行清除，或在重新開機後自然消失。
- 關閉視窗時若背景切換仍在執行，程式會先等待該次操作結束，再統一移除其建立的路由並保存停用狀態。
- 切換中途失敗時，程式會嘗試回復切換前的路由與開關狀態。
- 啟用期間每 5 秒透過原生 Windows IP Helper API 核對實際 `ActiveStore`，不會為每次檢查啟動 PowerShell；若 VPN 用戶端重下路由或刪除本程式路由，會自動補回。每分鐘也會重新核對 VPN 介面與一般網路閘道，Wi-Fi 重連或 DHCP 閘道改變時會原子替換舊路由；偵測到 VPN 已斷線時則移除殘留路由並關閉該分流。
- 網域與網址會解析為一或多個 IPv4 `/32` 路由；只有啟用設定真的包含網域或網址時，才會每 5 分鐘自動重新解析，且只有結果改變時才更新路由。
- 任一支援的 VPN 若下發 `0.0.0.0/0`（或成對的 `/1`）Full Tunnel，程式會保留該路由，但另外用四條 `/2` 路由把非指定 IPv4 流量導回原本的一般網路。`/2` 比 VPN 的 `/0` 或 `/1` 更精確，不會再靠介面 metric 碰運氣；使用者指定的 CIDR 或 `/32` 仍因前綴更精確而走指定 VPN。
- 若多個已啟用的 VPN 因外部重新連線而同時變成 Full Tunnel，健康檢查會保留原本負責一般網路繞行的那一個，並自動清除及停用其他衝突分流，避免路由停在無法收斂的狀態。

## 重要限制

這個程式管理的是 Windows 路由，不會修改或斷開 FortiClient、F5、Ivanti 本身，也不會移除公司 VPN 下發的路由。

FortiClient、F5 與 Ivanti 的 Full Tunnel 都會自動建立一般網路繞行。為避免多條全流量 VPN 互相競爭預設路由，同一時間只能啟用其中一個 Full Tunnel；其他原本就是 Split Tunnel 的 VPN 仍可同時管理不重疊的目的地。企業 VPN 可能透過 Route Monitor、Traffic Enforcement 或管理策略禁止本機繞行；遇到這種強制策略時，即使 Windows 路由建立成功，也無法保證一般網路可用。

建議先開啟本程式，填好目的地，再連線所需 VPN 並按「重新偵測 VPN」。程式通常也能在 VPN 已連線後，從 VPN 為伺服器保留的實體網路路由推回原本閘道；若無法安全判定，會阻擋啟用並顯示操作提示。

可接受混合輸入，例如：

```text
192.0.2.0/24
203.0.113.8/32
gitlab.example.test
http://gitlab.example.test:1500/
```

為避免意外接管所有流量，`0.0.0.0/0` 會被拒絕。

Windows 路由只能依目的 IP 選擇介面，無法依網址的通訊協定、路徑或連接埠分流。因此輸入 `http://gitlab.example.test:1500/` 時，程式會解析 `gitlab.example.test`，並讓解析所得 IP 的所有連接埠都走指定 VPN。

## 執行

需要 Windows 11、Rust stable，以及可用的 Windows PowerShell `NetTCPIP` / `NetAdapter` 模組。

```powershell
cargo run
```

Windows 只允許系統管理員修改路由。程式啟動時會自動顯示一次 UAC 權限確認；同意後會直接以系統管理員身分開啟，不再需要從畫面手動重新啟動。

## 驗證

```powershell
cargo test
cargo build --release
```

Release 執行檔會位於：

```text
target\release\rust-vpn-splitter.exe
```
